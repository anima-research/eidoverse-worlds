# Schools — shared, deterministic ambient fauna (DRAFT for review)

Status: proposal, 2026-09-25. Nothing here is implemented yet.

## Problem

Fish, birds and other ambient fauna must look the same to every participant, in
every renderer (three.js, Unreal, headless perception), including late joiners
and replays. Per-fish entities do not fit the budgets (512 entities, behavior emit
limits), and per-client simulations (the Unreal prototype's boids) diverge.

## Decision: parameters, not code

Same doctrine as `motion` and `grass` (DESIGN.md "Components"): a `school`
component carries parameters; a pure evaluator in `shared/school.js` maps
`(params, t)` to every fish's transform. No state, no integration, no traffic after
the component is written. Each renderer draws the result however it likes.

## Component

`comp {id, type: "school", data}` on any entity. The entity's live transform (spawn,
place, mount, motion) is the school's frame, so a school can ride a moving reef or
follow a vessel.

| Field | Meaning (metres, seconds, Y-up, entity-local) | Default / bounds |
| --- | --- | --- |
| `model` | library path of one fish GLB, +Z forward, origin at body centre | required |
| `count` | fish in this component | 1–256 |
| `seed` | integer; all variation derives from it | 0 |
| `region` | `{center:[x,y,z], size:[x,y,z]}` box the fish stay inside | required |
| `groups` | independent sub-schools sharing the region | 1–16, default 1 |
| `spread` | school radius as a fraction of the region's smallest half-extent | 0.05–1, default 0.25 |
| `speed` | cruise speed | 0.05–10, default 0.8 |
| `size` | `[min,max]` uniform scale range | default `[0.8,1.2]` |
| `wander` | 0 = tight formation, 1 = loose individual wandering | 0–1, default 0.4 |
| `t0` | epoch ms anchor, written by the author | server-resolved if absent |

Limits: 16 `school` components and 2048 fish per world (sequencer validator).
Unknown fields are ignored, not errors.

## Evaluator contract

```js
// shared/school.js
schoolParams(data) -> normalized params (clamps, defaults; same law everywhere)
schoolFish(params, tSeconds) -> [{ pos:[x,y,z], dir:[x,y,z], scale, phase }]
```

- Positions are entity-local; the caller composes the entity transform.
- **Group paths** are closed-form Lissajous curves: per group, three axes, each a sum
  of two sinusoids whose frequencies, phases and amplitudes come from the seeded
  generator, scaled so the path stays inside `region` shrunk by the group radius.
  Frequencies are chosen so path speed averages `speed`.
- **Fish offsets** are seeded points in an ellipsoid of radius `spread` around the
  group centre (flattened vertically), plus a small per-fish sinusoidal wander scaled
  by `wander`.
- **Heading** `dir` is the analytic time derivative of the position, normalized.
  **Tail phase** `phase` is `t × (speed / length)` plus a seeded offset, for the
  renderer's swim cycle.
- **Randomness**: mulberry32 seeded from `seed`, consumed in a fixed documented order
  (groups, then fish). No `Math.random`, no clock, no scene queries.
- Numerics use ordinary `Math.sin/cos`. This is **rendering-grade** determinism
  (agreement to ~1e-6 m), not simulation-grade. Fish must never feed collision,
  physics or rights decisions.

## Terrain and water

The evaluator does not query the scene. Authors keep `region` inside water and above
the seabed; `tools/water` authoring places regions from the level's bathymetry.
Renderers may hide a fish whose position is outside every water volume, but never move it.

## Local reactions (allowed divergence)

A renderer may displace fish away from nearby bodies (divers, submarines), as a purely
cosmetic offset that decays back to the shared position within about 2 s once the
disturbance ends. Reactions are not synced and are not part of the contract, like
grass bending.

## Steering with behaviors

A server behavior can change a school by rewriting its component (for example, move
`region` at dusk or raise `wander` when a crowd gathers). Renderers blend from the old
to the new evaluation over 3 s rather than jumping. Behavior emit budgets make this a
slow "brain", which is the intent.

## Projection and ports

- The sequencer folds `school` blindly, as it does every component; the validator only
  enforces the limits above.
- `render-scene` passes `data.school` through, normalized by `schoolParams`.
- `shared/conformance/school.json` (generated by `tools/school-vectors.ts`) pins
  evaluator outputs; the Unreal port must reproduce it in `Eidoverse.SchoolConformance`.
- three.js: one `InstancedMesh` per component, with a vertex swim cycle driven by `phase`.
- Unreal: instanced static meshes per component with the existing marine material's
  swim deformation, reusing `AMarineEcosystem` rendering but not its steering.
- Headless perception: `look` can report "a school of ~40 fish to the north-east" from
  the same evaluator.

## Open questions

1. Species definitions: inline `model`/`size`/`speed` (above), or a `defs/fauna/*.json`
   catalogue like flora, referenced by `species`? A catalogue keeps worlds small and lets
   Unreal attach native meshes per species.
2. Should `region` allow a list of boxes (following a reef)? Draft says one box; use
   several components for complex habitats.
3. Predators and interactions between schools are out of scope for version 1.
